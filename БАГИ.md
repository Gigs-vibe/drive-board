## 🔴 Критические — теряются данные пользователя · ✅ ИСПРАВЛЕНО в 1.8.3

**Как теперь устроено сохранение доски (общий ответ на №1–3):**
- запись идёт во временный файл, потом атомарная подмена — оборваться на полпути невозможно;
- прежняя удачная версия остаётся рядом как `drive-board.json.bak`;
- на диск не попадает мусор: перед записью содержимое проверяется на целостность;
- при чтении: файла нет → новая доска; файл повреждён → поднимаем `.bak`; не читается и копии
  нет → приложение честно сообщает и **переходит в режим только чтения**, ничего не затирая
  (а если из облака придёт целая доска — запись снова разрешается);
- при входе под другим аккаунтом доска прежнего **копируется** в `drive-board-<аккаунт>.json`.

### 1. Ошибка чтения файла доски = молчаливая потеря всей доски ✅🔍
`app.py:109-116` — `load()` на любую ошибку чтения (файл занят антивирусом, OneDrive, ошибка
кодировки) возвращает **пустую строку**, ровно как если бы доски не было вовсе. Интерфейс
делает вывод «пользователь новый», создаёт демо-доску и через секунду сохраняет её **поверх
настоящей**. Без резервной копии, без сообщения.
**Чинить:** различать «файла нет» и «прочитать не удалось»; при ошибке — не отдавать пустоту,
а сообщать интерфейсу об ошибке и НЕ сохранять поверх.

### 2. Запись доски не атомарна и без резервной копии ✅
`app.py:118-124` — файл открывается на запись (обнуляется), и только потом пишутся данные.
Обрыв в этот момент (выключение света, `os._exit(0)` при автообновлении) оставляет **пустой
файл**. Тест: при сбое записи файл превратился из 77 символов в 0.
**Чинить:** писать во временный файл и подменять через `os.replace`, плюс держать `.bak`
последней удачной версии.

### 3. Битый файл доски = приложение не запускается ✅🔍
`board.html:972` — `migrate(JSON.parse(local))` без `try/catch` (у командных досок защита есть,
у личной — нет). После бага №2 пользователь получает не просто пустую доску, а экран входа:
ошибка улетает в обработчик загрузки, который считает её «плохой сессией» и разлогинивает.
**Чинить:** обернуть в `try/catch`, при битом файле — поднять `.bak`, а не начинать с нуля.

### 4. Смена аккаунта затирает локальную доску прежнего ✅🔍
`board.html:1881-1884` — при входе под другим аккаунтом код ставит `state=defaultState()` и
**безусловно сохраняет** это в файл. Если прежний аккаунт работал офлайн и в облако ничего не
уезжало — его доска исчезает навсегда. Задумано было лишь «не показывать чужое».
**Чинить:** не сохранять до первой осознанной правки; либо складывать доску прежнего
пользователя в отдельный файл.

### 5. Медленный старт → доска подменяется демо-доской ❓🔍
`board.html:1816` — если мост к Python не готов за 600 мс (слабый ПК, холодный старт),
приложение стартует «как в браузере», читает пустое хранилище, строит демо-доску, а когда мост
появляется — сохраняет её в файл. В коде даже есть комментарий, что мост может опоздать.
**Чинить:** ждать мост дольше (или бесконечно, если запущены из .exe) и не сохранять,
пока доска не прочитана успешно.

### 6. «Очистить доску» стирает вообще всё ✅
`board.html:2537` — кнопка обещает удалить задачи, а на деле сбрасывает **архив, стикеры,
пресеты, загруженные картинки и видео, историю перемещений, интервал напоминаний и тему**,
после чего отправляет это в облако (то есть и на телефон). Тест: архив 1 → 0, стикеры 1 → 0,
пресеты 1 → 0, настройка напоминаний → пропала.
**Чинить:** чистить только карточки; в тексте подтверждения перечислить, что именно удаляется.

## 🟠 Серьёзные — неверное поведение, но данные целы · ✅ ИСПРАВЛЕНО в 1.8.3

Коротко, что сделано: `dragSrc` сбрасывается в `dragend` (№7) · `postpone` не трогает никакое
повторение — `if(cur.repeat)return` (№8) · сетевая ошибка на старте больше не разлогинивает,
сессию чистит только явный отказ сервера в токене (№9, №23) · `pushNow` запоминает доску перед
отправкой и снимает флаг только у неё (№10) · id колонок теперь равны их ролям, поэтому открытая
карточка переживает обновление доски из облака, плюс защита в «Сохранить» (№11) · после таймаута
повторяются только чтения, POST/PATCH/DELETE — нет (№12) · проверка Pro, админка и выход
переведены на `fetchWithTimeout` с обходом прокси (№13) · `repeats_today` не падает на битых
`repeatDays` и не глушит остальные напоминания (№14).

### 7. Карточка «уезжает» сама после отменённого перетаскивания ✅
`board.html:1391` — `dragSrc` очищается только при удачном броске. Если перетаскивание
отменили (отпустили над шапкой), метка остаётся. Следующий любой дроп на колонку (перетащили
картинку, выделенный текст) двигает **старую карточку**. Тест: карточка сама переехала в
«Готово», отметилась выполненной и попала в статистику.
**Чинить:** сбрасывать `dragSrc` в `dragend`, а в `commitDrop` проверять, что дроп относится
к нашему перетаскиванию.

### 8. «Отложить» превращает повторяющуюся задачу в разовую ✅
`board.html:1530` — защита стоит только на `repeat==='daily'`. У задачи «каждый вторник»
кнопка «+1 день» стирает расписание: тест показал `repeat:"weekly"` → `repeat:""`.
Напоминания по вторникам больше не приходят.
**Чинить:** `if(cur.repeat)return;`

### 9. Нет интернета при запуске = выход из аккаунта 🔍
`board.html:2611` — любая ошибка на старте (таймаут обновления токена за прокси) трактуется как
«сессия плохая»: сессия стирается, показывается экран входа, **локальная доска даже не
загружается**. Человек без сети не может открыть свои задачи.
**Чинить:** разлогинивать только при явном отказе сервера в токене; иначе — работать офлайн.

### 10. Переключение доски во время отправки теряет правки командной доски 🔍
`board.html:1050` — `pushNow()` снимает флаг «есть несохранённое» у той доски, которая открыта
**в момент ответа сервера**, а не той, что отправляли. Переключился между досками во время
отправки — правки второй доски помечаются отправленными и затираются следующей синхронизацией.
В соседней функции (`cloudPush`) такая защита уже есть, здесь забыли.

### 11. Правка задачи теряется при конфликте синхронизации ❓🔍
`board.html:1551` — при конфликте облако принимается принудительно (`adoptCloud`), а `migrate()`
выдаёт колонкам **новые id**. Открытая в этот момент карточка ссылается на исчезнувшую колонку:
нажатие «Сохранить» падает с ошибкой, правка пропадает. Для фонового обновления защита есть
(не трогаем, пока открыто окно), для конфликтного пути — нет.

### 12. Повтор запроса после таймаута может выполнить действие дважды ❓🔍
`board.html:934` — по таймауту 15 сек запрос не отменяется, а **повторяется через Python**.
Если сервер первый запрос всё же принял, получаем две одинаковые команды или два приглашения;
для сохранения доски — ложный «конфликт» и откат к облачной версии.
**Чинить:** повторять только чтения (GET), для остальных — показывать «попробуйте ещё раз».

### 13. Проверка Pro и админка не работают через прокси 🔍
`board.html:2021+` — `checkProStatus`, список Pro-пользователей, выдача Pro и выход из аккаунта
ходят «голым» fetch: без запасного пути через Python и без повтора при истёкшем токене. У
пользователя с Clash/V2Ray Pro просто не определяется, ошибка глушится пустым `catch`.

### 14. Битые данные повтора убивают ВСЕ напоминания ✅
`app.py:repeats_today` — если `repeatDays` пришёл строкой (правка с телефона, старый формат),
функция падает. Падение ловит общий обработчик цикла — и в этот проход **не отправляется ни
одно напоминание**, включая дедлайны других задач. Тест: `{"repeatDays":"вторник"}` → ошибка.
**Чинить:** приводить к списку чисел перед проверкой.

## 🔴🟠 Второй заход, 04.09.2026 — найдено после «всё закрыто» · ✅ ИСПРАВЛЕНО

Урок: чинить надо не тот путь, где баг заметили, а **все пути к тому же ресурсу**. Правка 1.8.3
закрыла запись на диск и оставила запись в облако.

### 25. 🔴 Режим «только чтение» не защищал облако — демо-доска уезжала на телефон ✅
`pushNow`, кнопка «Синхронизировать» и отправка профиля не проверяли `boardReadOnly`. Сценарий:
файл доски занят антивирусом → в памяти демо-доска → `if(session&&needPush)pushNow()` при старте
отправляет её в облако → следующая синхронизация телефона принимает демо-доску. **Хуже исходного
бага: терялась не локальная копия, а общая.** Теперь проверка стоит в самом `pushNow`.

### 26. 🔴 Доска прежнего аккаунта терялась, если у нового аккаунта есть облачная доска ✅
`archive_board` вызывался только внутри ветки «облако пустое». При обычном входе под вторым
аккаунтом ветка не срабатывала, и файл перезаписывался без копии. Теперь копия делается сразу
при обнаружении смены аккаунта — до любых записей.

### 27. 🔴 Поздний мост к Python по-прежнему затирал доску ✅
Ожидание моста удлинили до 6 секунд, но если он так и не поднялся, код читал пустой localStorage
и считал это «доски нет» — демо-доска уходила в файл. Теперь у ожидания три исхода: мост поднялся /
обычный браузер / **мост мёртв** — в последнем случае включается режим только чтения.

### 28. 🔴 Отказ записи проходил молча ✅
`Store.set` игнорировал `false` от `Api.save`. Диск переполнен или файл занят — приложение
считало, что сохранило. Теперь `set` возвращает результат, а пользователь видит предупреждение.

### 29. 🟠 Один сбой чтения выключал сохранение до перезапуска ✅
`boardReadOnly` ставился, но никогда не снимался при последующем успешном чтении.

### 30. 🟠 Дубли напоминаний и уведомления мимо Windows ✅
`whenReady` сдавался через 600 мс и помечал приложение «браузером»: JS-напоминания начинали
работать параллельно с Python (двойные пуши о дедлайнах), а уведомления команды шли через
браузерный механизм вместо системного. Теперь оба места ждут один и тот же признак.

### 31. 🟠 Повтор POST/PATCH/DELETE не только после таймаута ✅
Защита срабатывала лишь на таймаут; обрыв соединения по-прежнему повторял запрос — две команды,
два приглашения. Теперь повтор разрешён только для чтений и для мгновенных обрывов (<2с), когда
запрос заведомо не дошёл до сервера.

### 32. 🟠 Гонка записи: два сохранения писали в один временный файл ✅
pywebview зовёт мост из разных потоков. Добавлен замок; тест на 8 одновременных сохранений.

### 33. 🟠 Переименованная колонка возвращала стандартное имя ✅
`migrate()` перезаписывал заголовки из справочника. Теперь своё имя сохраняется, а старое
«Ежедневные задачи» по-прежнему обновляется на «Повторяющиеся задачи».

### 34. 🟡 Тест, который не мог провалиться ✅
